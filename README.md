# спанджбоб: прогноз потребления и сигналы изменений

Исследовательское решение задания СберИндекса. Реальные открытые муниципальные данные, восемь моделей прогноза, три причинных детектора изменений, ограниченный новостной эксперимент, оценка риска будущего устойчивого отклонения.

Репозиторий: https://github.com/Salamia2006/spandzhbob-sberindex (приватный). Для передачи жюри понадобится предоставить доступ либо отправить архив.

[Отчёт PDF](docs/spandzhbob_report.pdf) · [Презентация PDF](docs/spandzhbob_presentation.pdf)

## Результат

На тесте октября-декабря 2024 модель «сезонный + рост», выбранная по валидации для горизонта 3 месяца, получила MAE **996,83 руб.** против **2 284,09 руб.** у нашей конфигурации Prophet (снижение на **56,36%**).

На горизонте 1 месяц выбранное по валидации последнее значение получило MAE **2 691,08 руб.** против **2 516,94 руб.** у Prophet: **ухудшение на 6,92%**. Лучший результат сезонной модели на тесте не используется для заднего числа смены победителя.

**Предсказание реальных шоков не подтверждено.** Валидация экспериментального риска содержит ноль событий, тест - два. Детекторы оцениваются количественно на независимой синтетике; реальные сигналы не имеют экспертной разметки. Это честно отражено в отчёте.

## Запуск

Проверено на Windows, Python 3.12, CPU. Сеть нужна для установки библиотек и первой загрузки Chronos. Первичный Parquet уже включён, основной расчёт не требует доступа к СберИндексу.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-chronos.txt
python run.py
python benchmark_chronos.py
python analyze_changes.py
python -m unittest discover -s tests -v
python make_materials.py
```

Linux/macOS: активация `source .venv/bin/activate`. Для PDF необходим Arial в Windows или DejaVu Sans в Linux; на macOS укажите доступный путь шрифта в `make_materials.py`.

Упрощённая установка без фундаментальной модели: `pip install -r requirements.txt`, затем `python run.py`. Это пересоздаст таблицы для семи моделей; выполните `benchmark_chronos.py`, чтобы восстановить полное сравнение восьми. Уже посчитанные результаты всех восьми моделей входят в поставку.

Для автономной работы с предварительно скачанной моделью:

```powershell
python benchmark_chronos.py --model models/chronos-bolt-tiny
```

Модель зафиксирована по revision в `config.json`. Веса не включены в проект; их SHA-256 и сведения об окружении записаны в `results/environment.json`. `python run.py --chronos-cache models/chronos-bolt-tiny` также поддерживает единый прогон всех моделей.

Повторная загрузка первичных данных необязательна: `python download_data.py`. Если сервер Сбера требует недоверенный локальной системе корневой сертификат, скрипт по умолчанию откажет. Опция `--allow-untrusted-sber-certificate` явно включает исключение только для одной загрузки этого публичного архива; контроль SHA-256 сохраняется. Глобальные настройки TLS не меняются.

## Протокол

Панель: 2 031 МО с положительной полной историей января 2023 - марта 2024. Оценка: фиксированные 64 случайно выбранных МО, seed=42. Отбор не смотрит в будущие цели. Из 192 потенциальных тестовых строк один факт отсутствует, поэтому MAE каждой модели считается по одним и тем же 191 строкам.

Валидационные срезы: конец марта, апреля, мая 2024, горизонты 1 и 3 месяца. Тест: октябрь-декабрь 2024; для 1 месяца последовательные прогнозы, для 3 месяцев единый срез конца сентября. Признаки и обучение ограничены срезом; модельное семейство выбрано до теста.

Даты в CSV кодируют месяц первым числом; фактический момент выдачи прогноза интерпретируется как конец месяца `origin`. Это допущение о доступности данных, не утверждение о реальном календаре публикаций. Архивные версии отсутствуют: нет гарантии, что цифры текущей выгрузки совпадают с известными в 2024 году.

Общая модель прогнозирует будущие значения известных территорий. Географического holdout нет. Pooled R² чувствителен к различию уровней между МО; не интерпретируйте его как точность локального направления изменения.

Статистические детекторы работают с нормированными остатками фиксированного причинного сезонного прогноза. Прогноз-победитель и мониторинговая базовая модель разделены намеренно: смена семейства не меняет смысл исторического остатка. Сброс CUSUM/EWMA после сигнала не переобучает автоматически прогнозную модель; решение о переобучении должен принимать оператор.

Порог детектора выбирается на синтетической валидации, оценивается на другом seed; перенос на реальную экономику не доказывает его калибровку. На реальном участке выбранный CUSUM не дал сигналов; пороговый метод и EWMA дали по одному для МО 188. Нулевой сигнал не доказывает отсутствие шоков.

Новости: структурированные факты из девяти публикаций ЦБ. `published_at` - московское время; объявленная ставка используется после сообщения и не означает уже вступившую в силу ставку. Полные тексты, локальные новости, эмбеддинги и Росстат не интегрированы. Бустинг с новостями улучшил 1 месяц, ухудшил 3; надёжной общей пользы не установлено.

Будущий риск: два следующих относительных остатка больше 8% по модулю и одного знака. Это исследовательская proxy-цель. Разметка используется для обучения только после наступления обоих месяцев. Нельзя представлять эти метрики как оценку распознавания подтверждённых кризисов.

## Структура

```text
config.json                # параметры, срезы, seed, revision модели
run.py                     # сравнение прогнозов и выбор по валидации
benchmark_chronos.py       # фундаментальная модель и общее сравнение
analyze_changes.py         # детекторы и эксперимент риска
make_materials.py          # графики, отчёт, PDF-презентация
download_data.py           # опциональная проверяемая загрузка
src/data.py                # схема, качество данных, as-of новости
src/models.py              # модели прогноза
src/detection.py           # причинные детекторы
tests/test_integrity.py    # утечки, причинность, сопоставимость
data/                      # неизменённый источник и атрибуция
results/                   # численные результаты и графики
```
