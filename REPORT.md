Команда «спанджбоб»<br/>Методологический отчёт • 21 сентября 2026 года

Исследование на открытых муниципальных данных СберИндекса за 2023-2024 годы. Целевая переменная - оценка средних безналичных расходов жителей муниципального образования, рубли в месяц; категория «Все категории».


## Главный результат

Горизонт 1 мес.: по валидации выбрана модель Последнее значение. На тесте MAE = 2 691,1 руб., у Prophet = 2 516,9 руб.; увеличение ошибки относительно Prophet 6,9%.

Горизонт 3 мес.: по валидации выбрана модель Сезонный + рост. На тесте MAE = 996,8 руб., у Prophet = 2 284,1 руб.; снижение ошибки относительно Prophet 56,4%.

Сравнение относится к реализованной конфигурации Prophet и указанной выборке. Базовая модель организаторов не предоставлена, поэтому победа над их точной реализацией не установлена.

Предупреждение будущих шоков не подтверждено. В валидации риска нет положительных примеров, а в тесте только два события по условной разметке. Синтетический тест детекторов характеризует обнаружение уже начавшегося сдвига и не доказывает предсказание реальных кризисов.

Пакет содержит исходный код, JSON-конфигурацию, зафиксированные данные, таблицы всех прогнозов и метрик, тесты защиты от утечки будущего, этот отчёт и PDF-презентацию. Репозиторий проекта: https://github.com/Salamia2006/spandzhbob-sberindex (приватный, доступ по приглашению владельца).


## 1. Данные и ограничения измерения

Первичный файл содержит 303,126 записей, 2190 муниципалитетов и 24 месяца. Условие включения в обучающую панель: ненулевые и непропущенные значения за январь 2023 - март 2024. Его проходят 2031 территорий. Для сопоставления всех моделей выбраны 64 территории без возвращения, генератор NumPy, seed=42. Выбор не использует будущие целевые значения.

Поставщик описывает показатель как средние безналичные потребительские расходы на основе моделей транзакционных данных. Это не общий оборот муниципалитета и не весь объём потребления населения. Номинальный рост смешивает изменение покупок и цен; дефлятирование не выполнено.

В описании поставщика поле называется consumption, фактическая колонка - value; загрузчик поддерживает оба имени. У категорий удаляются внешние пробелы. «Все категории» уже включает перечисленные и другие траты: суммирование её с подкатегориями создало бы двойной счёт.

Дубли ключей и отрицательные значения проверяются до обучения. В выбранной панели всего 54 пропусков. Обучающие окна с пропусками исключаются; на момент прогноза допускается только перенос последнего известного значения вперёд. Отсутствующий факт не участвует в метриках; модели оцениваются на одинаковых ключах.

territory_id - идентификатор МО в постоянных границах; названия и расшифровка ОКТМО в архиве отсутствуют. Поэтому реальные примеры обозначены кодами, без выдуманных географических названий. Индексы доступности рынков 2024 года и расстояния на конец 2024 года не включены в исторические прогнозы: нет подтверждения их доступности в ранние даты.

Набор опубликован ретроспективно. Архивных версий и календаря первоначальной публикации наблюдений нет. Эксперимент проверяет порядок наблюдений, но не воспроизводит доступность данных в реальном времени. Принято допущение: значение месяца доступно в его конце. Для внедрения необходимы даты available_at и повторный тест с реальным лагом.

## 2. Архитектура и модели

Данные → проверка → временные срезы → прогноз → остатки → детектор → сигнал для проверки. Параллельный блок: признаки только опубликованных новостей → прогноз и экспериментальная вероятность будущего устойчивого отклонения.

Общие модели обучаются по всем доступным территориям, что увеличивает число примеров при короткой истории. В каждой строке используются лаги 1, 2, 3, 6, 12; среднее за три и стандартное отклонение за шесть месяцев; логарифм текущего уровня; номер шага; синус/косинус месяца; известный прошлогодний целевой месяц. Масштаб - последнее известное значение; целевая переменная - отношение будущего расхода к этому уровню. Предсказания ограничиваются снизу нулём.

Гиперпараметры зафиксированы заранее; выбор семейства выполняется по валидационному MAE отдельно для каждого горизонта. Prophet на истории меньше двух лет может нестабильно разделять тренд и годовую сезонность. Его конфигурация является прозрачной базой сравнения, а не исчерпывающим поиском лучших параметров.

Chronos опубликован после части исторических дат теста. Это современное ретроспективное сравнение, а не доказательство того, что такую систему можно было использовать в начале 2024 года. Возможное пересечение предобучения с экономическими рядами не аудировано.


## 3. Протокол проверки прогнозов

MAE = среднее |факт - прогноз|, в рублях; меньше - лучше. Для горизонта три месяца каждый шаг учитывается с одинаковым весом. R² = 1 - сумма квадратов ошибок / сумма квадратов отклонений факта от общего среднего; больше - лучше. Это pooled R²: различия уровней между МО могут делать его высоким даже при слабой динамике внутри ряда.

Перекрывающиеся валидационные горизонты сохраняются как разные задачи по дате выдачи прогноза. Для интервала разницы MAE используется 1 000 повторов кластерного bootstrap по муниципалитетам с сохранением всех их временных наблюдений. Он не учитывает полностью общие экономические шоки; независимых тестовых месяцев всего три.

Обучение общей модели использует истории тех же территорий, которые встречаются на тесте: это прогноз будущего известных МО. Перенос на ранее невиденные территории этим протоколом не проверяется.


## Защита от утечки

Тесты меняют все будущие значения и проверяют неизменность прогноза; проверяют невидимость будущих новостей и совпадение префикса работы детектора; проверяют общий набор тестовых ключей и выбор победителя только по валидации. Пропуски не заполняются из будущего.

Горизонт 3 мес.: разница MAE Prophet минус Сезонный + рост = 1 287,3 руб.; 95% кластерный интервал [1 091,8; 1 474,7]. Положительная разница означает меньшую ошибку выбранной модели.

Все индивидуальные прогнозы сохранены в results/predictions.csv, включая дату выдачи, дату цели, шаг, территорию, факт и модель. Валидационные результаты и число оценённых строк - в results/metrics.csv. Результат на 64 случайно выбранных МО не следует без дополнительного теста распространять на всю страну.

На горизонте один месяц выбор по валидации не перенёсся на IV квартал: последнее значение проиграло Prophet. Сезонная модель дала лучший тестовый результат, но заменить ею выбранную модель после просмотра теста означало бы утечку. На горизонте три месяца сезонная модель опередила Prophet на валидации лишь примерно на 5 руб.; уверенность в выборе семейства ограничена.

## Интерпретация сигналов

Сезонные пики, изменение охвата транзакций и ошибки оценивания поставщика могут имитировать шок. При эксплуатации сигнал должен содержать дату доступности факта, величину отклонения, базовый прогноз и ссылки на уже опубликованные релевантные сообщения.

В этом коротком реальном тесте выбранный CUSUM не выдал сигналов. Другие методы отметили МО 188: абсолютный порог в ноябре 2024 (остаток -16,1%), EWMA в декабре (-22,7%). Это объясняет расхождение на графике, но не устанавливает причину падения расходов и не подтверждает структурный сдвиг.


## 6. Обнаружение структурных изменений

Базовый остаток: (факт - сезонный прогноз с поправкой на рост) / прогноз. Центр и масштаб фиксируются по январю-июню 2024 по обучающей панели: медиана и 1,4826 × MAD, нижняя граница масштаба 0,01. Мониторинг реальных данных начинается в июле. Каждый новый факт поступает в детектор один раз.

Сравниваются абсолютный порог, двусторонний CUSUM и EWMA. CUSUM накапливает положительные и отрицательные отклонения с дрейфом 0,5. EWMA использует сглаживание 0,3. После сигнала накопители сбрасываются; на реальной панели следующие три наблюдения подавляют повторное оповещение.

Для независимой численной проверки созданы два набора по 300 рядов длиной 120: 150 контрольных и 150 со сдвигом на шаге 80. Виды изменений - ступень 1,5σ, ступень 3σ и плавный рост до 3σ, оба знака. Валидация seed=101, тест seed=202. Шум стандартный гауссовский; это сценарный стресс-тест, а не модель распределения реальных расходов.

Порог выбирается из 2, 3, 4, 5, 6, 8 по максимальной событийной F1 на синтетической валидации. Сигнал засчитывается, если попал в первые 12 шагов после изменения; сопоставление один-к-одному. Любой другой сигнал, включая повторный, считается ложным. Синтетическая пауза между сигналами - 12 шагов; задержка дана в наблюдениях, не днях.

По валидации выбран cusum, порог 8. Применение к реальным данным сохранено в real_alerts.csv. Подтверждённых истинных точек изменений нет, поэтому precision и recall на реальных расходах не заявляются. Пороги, перенесённые с синтетики, требуют калибровки на размеченной реальной истории.


## 7. Новости и раннее предупреждение

Минимальный новостной корпус: девять официальных сообщений Банка России об объявленной ключевой ставке, декабрь 2023 - декабрь 2024. Это узкий тематический набор, а не полный мониторинг СМИ. Дата и время - время публикации по Москве; announced rate может отличаться от действующей ставки до даты вступления решения в силу.

Присоединение as-of: published_at ≤ конец месяца выдачи прогноза. Признаки: последняя объявленная ставка, сумма изменений и число публикаций в последние 31 день. Для нескольких будущих шагов признаки заморожены на момент выдачи: будущие решения не подставляются. Сравнение с тем же бустингом без новостей изолирует добавление этих признаков, но не устанавливает причинный эффект ставки.

Горизонт 1: MAE бустинга без новостей 3 836,3; с новостями 3 569,7 руб. Разница с новостями минус без = -266,6 руб.

Горизонт 3: MAE бустинга без новостей 2 786,4; с новостями 3 360,6 руб. Разница с новостями минус без = 574,1 руб.

Экспериментальная цель риска: в двух следующих месяцах остатки превышают 8% по модулю и имеют один знак. Это условный признак устойчивого отклонения, а не экспертная разметка структурного изменения. Он становится известен только через два месяца. Признаки риска - текущий и предыдущий остаток, модуль и изменение, опционально новости.

Обучающие даты выдачи: февраль-апрель 2024; их цели известны к июню. Валидация: июнь-июль, цели известны к сентябрю. Тест: сентябрь-октябрь, цели известны к декабрю. Обучается LogisticRegression C=0,1 с масштабированием только по обучению; базовая модель предсказывает частоту события в обучении.

На валидации нет положительного класса: порог нельзя подобрать по F1. Применён фиксированный порог 0,5. На тесте всего два положительных примера, поэтому устойчивость метрик не установлена. Данный блок не готов к автономной выдаче предупреждений. Необходимо расширить историю и экспертно разметить события; отрицательный результат сохранён без подбора определения шока под тест.


## 8. Воспроизводимость и итог

Python 3.12. Из папки проекта: создать виртуальное окружение, установить requirements-chronos.txt, выполнить python run.py, затем python benchmark_chronos.py, python analyze_changes.py, python -m unittest discover -s tests -v и python make_materials.py. Первая загрузка Chronos требует сети; основной набор данных входит в архив. Для полностью автономного запуска передать локальный каталог модели через --model.

config.json хранит выборку, seed, горизонты, временные срезы и основные гиперпараметры. Формулы и параметры детекторов описаны в src/detection.py; пороги риска и синтетического эксперимента зафиксированы в analyze_changes.py. Замена файла данных проверяется по SHA-256. Фактические версии пакетов и хеш весов сохранены рядом с результатами.

Что подтверждено: воспроизводимое сравнение прогнозов на одной временной схеме; численные метрики MAE и R²; использование реального набора СберИндекса; запуск фундаментальной модели; работа причинных детекторов; проверка ограниченного новостного расширения. Что не подтверждено: предсказание реальных шоков, превосходство над неизвестной моделью организаторов, качество на новых МО и работа с реальными задержками публикации.
